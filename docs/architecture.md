# Expenses Tracker — Architecture

## Assumptions

Each item below is a decision made where the brief was silent. Changing any of them changes the contract in `docs/openapi.yaml`.

| # | Topic | Decision |
|---|---|---|
| A1 | Users and auth | **Single user, no authentication.** The API is meant for a personal machine or trusted home network. No login, no roles, no user ID on records. Running it on a public network is out of scope (see Security model). |
| A2 | Currency | **One currency per installation**, set by `APP_CURRENCY` (ISO 4217 code, default `USD`). Expenses store no currency. The code is exposed by `GET /api/v1/metadata` and in the monthly summary so the app can format amounts. No conversion. |
| A3 | Amount | Decimal, **> 0**, at most 2 fraction digits and 10 integer digits (`max 9999999999.99`). Sent as a JSON number, handled as `BigDecimal` on both server and Android (never `double`/`float`). Stored as `NUMERIC(12,2)`. |
| A4 | Category model | **Fixed enum**, not user-editable: `FOOD, GROCERIES, TRANSPORT, HOUSING, UTILITIES, HEALTH, ENTERTAINMENT, SHOPPING, EDUCATION, TRAVEL, OTHER`. Exposed with display names by `GET /api/v1/metadata`, so the app does not hardcode labels. Custom categories are out of scope. |
| A5 | Date | Calendar date only (`LocalDate`, ISO `YYYY-MM-DD`), no time or time zone. **Must not be in the future** relative to the server's local date (server uses an injected `java.time.Clock` so tests can fix "today"). |
| A6 | Note | Optional, max 500 characters. Leading/trailing whitespace is trimmed; a blank note is stored as `null`. |
| A7 | Month | Written as `YYYY-MM` (`java.time.YearMonth`). A month covers its first to last day inclusive. |
| A8 | Filtering | `GET /api/v1/expenses` takes optional `month` and `category`; both together are ANDed. With neither, all expenses are returned. No pagination (one user, small volume). Ordering: `date` desc, then `id` desc. |
| A9 | Monthly totals | `GET /api/v1/summaries/monthly?month=YYYY-MM` (month required) returns the grand total, the count, and one row per category **that has at least one expense** in that month, ordered by total desc, then category code asc. A month with no expenses returns total `0.00` and an empty list. |
| A10 | Edit | `PUT` replaces the whole expense (same body as create). No partial `PATCH`. No optimistic locking (single user). |
| A11 | Delete | Hard delete, `204 No Content`. Deleting an unknown ID returns `404`. |
| A12 | Android connectivity | Online-only, no offline cache or sync. Base URL defaults to `http://10.0.2.2:8080/` (emulator → host) and can be changed in an in-app Settings screen (stored in `SharedPreferences`), so the release APK works against a backend on a LAN IP. Cleartext HTTP is allowed because there is no TLS in a local single-user setup. |
| A13 | Android SDK levels | `minSdk 26` (native `java.time`), `targetSdk`/`compileSdk` = latest stable at build time. |
| A14 | Versioning | API path prefix `/api/v1`. App version `1.0.0`. |

## Goal

Expenses Tracker lets one person record what they spend and see where the money goes each month. They log an expense with an amount, a category, a date and an optional note, and can edit or delete it later. They browse expenses filtered by month and/or category, and see monthly totals broken down by category. The product is a Spring Boot REST API, shipped as a single executable JAR with an embedded database, plus a native Android app that uses it.

### Out of scope
- Multiple users, accounts, login, sharing.
- Multiple currencies or currency conversion.
- User-defined categories, budgets, recurring expenses, receipts/attachments.
- Offline mode and sync on Android; iOS; web front end.
- Import/export (CSV etc.), charts beyond a per-category totals list.
- Docker, cloud deployment, TLS termination.

## Domain model

### `Expense` (JPA entity, table `expense`)

| Field | Java type | Column | Rules |
|---|---|---|---|
| `id` | `Long` | `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | Server-assigned, read-only. |
| `amount` | `BigDecimal` | `amount NUMERIC(12,2) NOT NULL` + `CHECK (amount > 0)` | Required; `> 0`; `@Digits(integer = 10, fraction = 2)`. |
| `category` | `Category` (enum) | `category VARCHAR(32) NOT NULL` (`@Enumerated(STRING)`) | Required; one of the enum values (A4). |
| `date` | `LocalDate` | `expense_date DATE NOT NULL` | Required; not after today (A5). |
| `note` | `String` | `note VARCHAR(500) NULL` | Optional; trimmed; max 500; blank → `null` (A6). |
| `createdAt` | `Instant` | `created_at TIMESTAMP WITH TIME ZONE NOT NULL` | Set on insert, read-only. |
| `updatedAt` | `Instant` | `updated_at TIMESTAMP WITH TIME ZONE NOT NULL` | Set on insert and every update, read-only. |

Index: `idx_expense_date_category ON expense (expense_date, category)`.
Migration: `V1__create_expense.sql` — portable SQL that runs on H2 (`MODE=PostgreSQL`) and PostgreSQL.

### `Category` (Java enum)
Each constant carries a display name: `FOOD("Food")`, `GROCERIES("Groceries")`, `TRANSPORT("Transport")`, `HOUSING("Housing")`, `UTILITIES("Utilities")`, `HEALTH("Health")`, `ENTERTAINMENT("Entertainment")`, `SHOPPING("Shopping")`, `EDUCATION("Education")`, `TRAVEL("Travel")`, `OTHER("Other")`.

### DTOs (records, in `api.dto`)
- `ExpenseRequest(BigDecimal amount, Category category, LocalDate date, String note)` — create and update body, Bean Validation annotations as above.
- `ExpenseResponse(Long id, BigDecimal amount, Category category, LocalDate date, String note, Instant createdAt, Instant updatedAt)`.
- `MonthlySummaryResponse(String month, String currency, BigDecimal total, long count, List<CategoryTotal> categories)`; `CategoryTotal(Category category, BigDecimal total, long count)`.
- `MetadataResponse(String currency, List<CategoryInfo> categories)`; `CategoryInfo(String code, String displayName)`.

Amounts in responses are always serialized with scale 2 (e.g. `12.50`, `0.00`).

## API summary

Full contract: `docs/openapi.yaml` (OpenAPI 3.1, the single source of truth).

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/v1/expenses?month=&category=` | List expenses, optionally filtered by month and/or category |
| POST | `/api/v1/expenses` | Create an expense → `201` + `Location` |
| GET | `/api/v1/expenses/{id}` | Get one expense |
| PUT | `/api/v1/expenses/{id}` | Replace an expense |
| DELETE | `/api/v1/expenses/{id}` | Delete an expense → `204` |
| GET | `/api/v1/summaries/monthly?month=` | Monthly total and totals per category |
| GET | `/api/v1/metadata` | Currency code and category list with display names |
| GET | `/actuator/health` | Liveness (Spring Boot Actuator) |

## Security model

- **No authentication** (A1). Spring Security is **not** included. Every endpoint is open.
- The server binds to `0.0.0.0:${PORT:8080}` so a phone on the same LAN can reach it. The README must warn that the API is unauthenticated and must only run on a trusted network.
- Input validation on every request body and query parameter (Bean Validation + typed parameters). Unknown enum values, malformed dates/months and malformed JSON return `400`.
- Data access through Spring Data JPA with bind parameters only; no string-built SQL.
- Notes are user data: never logged.
- Actuator exposes only `health` and `info`.
- No secrets exist in this design. `DB_PASSWORD` for the optional Postgres profile comes from the environment and is documented in `.env.example`.

## Persistence

- Default: embedded **H2 file** database at `./data/expenses` (`jdbc:h2:file:./data/expenses;MODE=PostgreSQL;AUTO_SERVER=TRUE`), so `java -jar expenses-tracker-1.0.0.jar` works with no install.
- Optional profile `postgres`: `--spring.profiles.active=postgres` with `DB_URL`, `DB_USER`, `DB_PASSWORD`.
- Schema only from **Flyway** (`src/main/resources/db/migration`); `spring.jpa.hibernate.ddl-auto=validate`; `open-in-view=false`.
- Tests: H2 in-memory (`jdbc:h2:mem:`), Flyway applied. No Testcontainers.

## Error format

All errors are **RFC 9457 problem details** with `Content-Type: application/problem+json`, produced by `ApiExceptionHandler` (built on Spring's `ProblemDetail`).

| Situation | Status | `type` | Notes |
|---|---|---|---|
| Body field validation fails | 400 | `/problems/validation-error` | `errors` array of `{field, message}` |
| Bad query parameter (bad `month`, unknown `category`, non-numeric `id`) | 400 | `/problems/validation-error` | `errors` names the parameter |
| Malformed / unreadable JSON, unknown enum in body | 400 | `/problems/malformed-request` | `errors` names the field when it can be determined |
| Expense ID not found | 404 | `/problems/not-found` | |
| Unsupported method / media type | 405 / 415 | `/problems/http-405`, `/problems/http-415` | Framework-generated; `type` set explicitly because Spring 7 omits `about:blank` |
| Unmapped path | 404 | `/problems/http-404` | Framework-generated |
| Unexpected error | 500 | `/problems/http-500` | Generic `detail`; stack trace only in the server log |

Example:
```json
{
  "type": "/problems/validation-error",
  "title": "Validation failed",
  "status": 400,
  "detail": "Request has 1 invalid field",
  "instance": "/api/v1/expenses",
  "errors": [{ "field": "amount", "message": "must be greater than 0" }]
}
```

## Android app

- Package / applicationId `com.factory.expenses`, single-activity with fragments and Navigation component, MVVM (`ViewModel` + `LiveData`), Retrofit + Gson (with `BigDecimal` and `LocalDate`/`YearMonth`/`Instant` type adapters), Material 3.
- Layers: `data.api` (Retrofit interface mirroring the contract, DTOs), `data.repository` (`ExpenseRepository`, maps problem details into a `ApiError` with field errors), `ui.list`, `ui.edit`, `ui.summary`, `ui.settings`.
- Screens:
  1. **Expenses list** — month selector (prev/next, defaults to current month), category filter (All + each category), list rows show date, category, amount, note preview; FAB → add. Tapping a row → edit.
  2. **Add / edit expense** — amount, category dropdown (from `/metadata`), date picker (no future dates), note; Save; on edit, Delete with confirmation dialog. Server field errors shown on the matching input.
  3. **Monthly summary** — month selector, grand total, per-category totals with counts.
  4. **Settings** — API base URL (validated as `http(s)://…/`).
- Amounts formatted with the currency from `/metadata` via `NumberFormat.getCurrencyInstance` + `Currency.getInstance(code)`.
- Network errors and 5xx show a retryable error state; no crash on server down.

## Non-functional targets

- **Coverage:** ≥ 80% line coverage (JaCoCo) enforced in `./gradlew check` in `backend/`; for `android/`, ≥ 80% line coverage on `data` and `ui.*.ViewModel` classes via unit tests (UI classes excluded).
- **Static analysis:** Spotless (google-java-format) and SpotBugs (no high-priority findings) in `check`.
- **Latency:** p95 < 200 ms for every endpoint at 10,000 stored expenses on a developer laptop with the H2 file DB.
- **Startup:** JAR ready (health `UP`) in < 15 s on a developer laptop.
- **Logging:** SLF4J/Logback to stdout. One INFO line per request: method, path, status, duration ms. WARN for 4xx handled by the advice (without bodies), ERROR with stack trace for 5xx. No note contents or request bodies in logs.
